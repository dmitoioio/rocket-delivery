# supabase/

Міграції, RLS-політики та Edge Functions.

```
supabase/
├── migrations/    SQL-міграції (порожньо — етап 3 дорожньої карти)
├── policies/      RLS-політики, якщо виносяться окремо від міграцій
├── functions/     Edge Functions
└── seed.sql       Дані для локальної розробки та staging
```

## ⛔ Перед першою міграцією

**Не створювати жодної таблиці, поки не прочитано схему CSTL_NEWS.**

Rocket Delivery живе в **тому самому проєкті Supabase**, що й cstllife ([ADR-0001](../docs/adr/0001-shared-supabase-database.md)). Створити `orders` наосліп — це або конфлікт із наявною таблицею, або друга таблиця замовлень поруч із першою.

Порядок: етап 2 дорожньої карти (дослідження CSTL_NEWS) → потім етап 3 (міграції).

Проєктна схема, яку треба реалізувати: [docs/04-data-model.md](../docs/04-data-model.md).

## Правило мержу міграцій

Міграція **не мержиться**, якщо в тому ж PR немає:

- [ ] `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY` на кожній новій таблиці
- [ ] окремих політик на `SELECT` / `INSERT` / `UPDATE` / `DELETE` (не одна на `ALL`)
- [ ] тесту, що **анонім** не читає нічого
- [ ] тесту, що **чужий курʼєр** не читає чужі замовлення
- [ ] тесту, що **клієнт** не читає чужі замовлення
- [ ] тесту, що **заклад** не читає замовлення іншого закладу
- [ ] перевірки Realtime-підписки анонімом (RLS не завжди успадковується автоматично)

Це не бюрократія. У проєкті вже стався витік через RLS на приватних повідомленнях — цей чек-лист існує саме тому.

Повний контекст: [docs/05-roles-auth-rls.md](../docs/05-roles-auth-rls.md).

## Іменування міграцій

```
NNNN_коротка_суть.sql
0001_enums_and_core_tables.sql
0002_rls_orders.sql
```

Міграції **не редагуються після мержу**. Виправлення — нова міграція.

## Команди

```bash
npm run db:diff -- назва_міграції   # згенерувати міграцію з різниці
npm run db:push                     # застосувати
npm run db:reset                    # перезібрати локальну БД + seed
```

## Staging

Тестувати RLS на продакшені зі справжніми даними жителів — неприйнятно, особливо після попереднього витоку. Окремий проєкт Supabase для staging потрібен **до** початку етапу 3. Питання Q10 у [docs/11-open-questions.md](../docs/11-open-questions.md).
