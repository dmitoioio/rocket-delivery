# src/ — вихідний код

Каркас під перенесення прототипу. Структура задана заздалегідь, щоб один HTML-файл розкладався в неї механічно, а не «як вийде».

```
src/
├── app/
│   ├── main.js          Точка входу: ініціалізація, роутинг за роллю
│   ├── router.js        Навігація між екранами
│   └── state.js         Спільний стан застосунку
│
├── features/
│   ├── auth/            Логін, RoleGuard, зміна пароля при першому вході
│   ├── courier/         Черга, активне замовлення, історія, профіль
│   ├── admin/           Дашборд, курʼєри, готівка, аналітика, зарплата, фото, журнал
│   └── shared/          StatusStepper, OrderCard, CountdownTimer, PhotoCapture,
│                        MoneyAmount, SwipeTabs
│
├── lib/
│   ├── supabase.js      Клієнт, ініціалізація, обробка сесії
│   ├── db.js            🔑 ЄДИНИЙ шар доступу до даних
│   ├── realtime.js      Підписки на канали
│   ├── geo.js           Geolocation API + Wake Lock + буферизація
│   ├── maps.js          Leaflet, тайли, Directions API
│   ├── offline.js       Черга дій в IndexedDB + idempotency
│   └── format.js        Гроші, дати (Europe/Kyiv), відмінювання
│
└── styles/
    ├── tokens.css       Кольори, шрифти, розміри — дизайн-система
    ├── base.css         Скидання, 100dvh, viewport-фікси
    └── components.css   Компоненти
```

## Два правила структури

**1. Жодних прямих викликів Supabase з екранів.** Усе через `lib/db.js`. Це дає єдину точку для обробки помилок, офлайн-черги, ідемпотентності й логування. Без цього правила `supabase.from('orders')` розповзеться по 20 файлах, і додати офлайн-режим стане неможливо.

**2. Мобільні фікси живуть у `base.css`, а не «пригадуються» під час тестування.** `100dvh`, viewport без пінч-зуму, медіа-запити в кінці каскаду — це вже коштувало часу один раз (див. [docs/08](../docs/08-design-system.md)).

## Порядок перенесення прототипу

1. Покласти `rocket-delivery-app.html` у [`prototype/`](../prototype/) — as-is, не редагувати.
2. Витягти CSS → `styles/`, розділивши на токени / базу / компоненти.
3. Витягти спільні UI-елементи → `features/shared/`.
4. Розкласти екрани по ролях, **зберігаючи поведінку 1:1**.
5. Замінити `let queue = [...]` на виклики `lib/db.js`.
6. Підключити Realtime.

Крок 5 — останній, не перший. Спершу структура на тих самих даних у памʼяті, потім заміна джерела. Так на кожному кроці видно, що нічого не зламалось.
