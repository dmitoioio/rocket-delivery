# 07 — Геолокація курʼєра

## Джерело координат

Телефон курʼєра через **Geolocation API браузера**. Не окремий апаратний GPS-трекер.

Координати передаються **тільки під час активного замовлення**. Після `delivered` або переходу в офлайн трекінг зупиняється. Це не лише економія батареї — це вимога приватності: роботодавець не має права бачити, де працівник о другій ночі.

## Обмеження iOS — головна технічна межа проєкту

Safari і PWA на iOS **не підтримують фонове виконання коду**. Немає Background Sync, немає фонової геолокації. Це стосується і встановленого на головний екран PWA — **встановлення саме по собі фон не вмикає**.

Наслідок: геолокація оновлюється **тільки поки застосунок відкритий на екрані**. Згорнув застосунок → трекінг зупинився. Заблокував екран → трекінг зупинився.

## Рішення для MVP: Screen Wake Lock API

Не дає екрану засинати, поки триває доставка. Курʼєр кріпить телефон на скутері екраном угору.

| Платформа | Підтримка |
|---|---|
| iOS Safari | з 18.4+ (у встановлених PWA раніше був баг, виправлений саме в 18.4) |
| Android Chrome | з 84+ |

Тобто працює на переважній більшості сучасних пристроїв. Обґрунтування вибору: [ADR-0003](adr/0003-wake-lock-for-geolocation.md).

### Що треба реалізувати правильно

```js
// Wake Lock треба перезапитувати після повернення з фону —
// система знімає його при переході на іншу вкладку/застосунок
document.addEventListener('visibilitychange', async () => {
  if (document.visibilityState === 'visible' && hasActiveOrder()) {
    await requestWakeLock();
  }
});
```

Це найчастіша помилка реалізації: Wake Lock узяли один раз при старті доставки, курʼєр відповів на дзвінок — і lock зник назавжди.

## Батарея — операційна проблема, яку код не вирішує

Увімкнений екран на повну яскравість + постійний GPS + мобільна мережа = **телефон сідає за 2–3 години**. Зміна курʼєра триває довше.

Wake Lock не вирішує цю проблему, він її створює.

**Операційна вимога, а не технічна:** тримач на кермі **із зарядкою від скутера** або повербанк. Без цього трекінг помре посеред зміни, і жодний код цього не виправить. Баг B21.

Додатково: писати `courier_locations.battery_level` (Battery Status API там, де доступний) — щоб адмін бачив у дашборді, що телефон курʼєра на 8%, **до** того як звʼязок зникне.

## Дозвіл на геолокацію

Geolocation API вимагає HTTPS і явного дозволу користувача.

**Правило:** якщо курʼєр не дав дозвіл — він **не може перейти в онлайн**. Не «може, але без карти». Замовлення без трекінгу — це замовлення, за яким ніхто не бачить, де їжа.

Екран онлайну має чесно пояснювати, чому дозвіл потрібен, і вести в налаштування, якщо його вже відхилили (браузер не покаже запит удруге).

## Частота й обсяг даних

| Параметр | Значення |
|---|---|
| Інтервал оновлення | 8 секунд (компроміс: точність vs батарея) |
| Мінімальний зсув для відправки | 20 метрів — не слати ту саму точку, коли курʼєр стоїть |
| Канал | Realtime **Broadcast**, не `INSERT` у таблицю |
| У таблиці | Тільки остання позиція, `UPSERT` по `courier_id` |
| Трек-лог | Розріджений (1 точка на 60 сек), окрема партиційована таблиця, TTL 30 днів |

> 🔴 Наївна реалізація «`INSERT` кожні 5 секунд» дає ~17 000 рядків на курʼєра за 24 години. Пʼятеро курʼєрів за місяць — понад 2,5 мільйона рядків заради даних, які нікому не потрібні через годину. Баг B16.

## Поганий звʼязок у селі

Це не крайній випадок, це нормальний режим роботи в Олиці й довколишніх селах.

**Потрібно:**
- локальна черга дій (IndexedDB): курʼєр тисне «доставлено» без мережі → дія стає в чергу з `idempotency_key` і відправляється при відновленні звʼязку;
- UI чесно показує «не відправлено, чекаю мережу», а не вдає успіх;
- координати в офлайні буферизуються й дописуються пачкою.

Без цього курʼєр натисне «доставлено», побачить успіх, а замовлення залишиться висіти. Баг B23.

## Що бачить клієнт

Клієнт бачить точку курʼєра на карті на сторінці свого замовлення — **тільки поки замовлення активне**. Після `delivered` карта замінюється підсумком.

Клієнт **не бачить**: інших замовлень курʼєра, його маршруту до цього, його імені у відриві від замовлення, номера телефону курʼєра напряму (звʼязок через кнопку дзвінка з маскуванням номера — або принаймні з логуванням).

## Довгострокова альтернатива

Якщо знадобиться справжній фоновий трекінг (згорнутий застосунок, заблокований екран):

| Варіант | Плюси | Мінуси |
|---|---|---|
| Нативна обгортка (Capacitor) | Реальний фон, push, доступ до заліза | App Store/Play, підписи, окремий реліз-цикл |
| Апаратний GPS-трекер на скутері | Не залежить від телефона й батареї | Залізо, SIM, вартість, не показує «курʼєр біля дверей» |

Обидва — після пілоту. Wake Lock достатній, щоб довести модель.

## Карти

- **Тайли:** публічні тайли OpenStreetMap заборонені їхньою usage policy для продакшену. Потрібен свій провайдер (MapTiler / Stadia) або self-host. Баг B20.
- **Маршрут:** прототип використовує безкоштовний Google Maps embed (`saddr/daddr&output=embed`). Спосіб неофіційний, ненадійний для велосипедного режиму в сільській місцевості, **і передає адресу клієнта в Google через URL без згоди**. У продакшені — платний Directions API з ключем, обмеженим по домену. [ADR-0007](adr/0007-maps-provider.md), баг B19.
