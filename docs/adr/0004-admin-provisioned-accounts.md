# ADR-0004: Облікові записи курʼєрів створює адміністратор

**Статус:** Прийнято

## Контекст

Курʼєри — штатні співробітники (або підрядники) cstllife, не відкритий пул виконавців. Це не Glovo: людину наймають, а не реєструють.

## Рішення

**Самореєстрації немає.** Адміністратор створює обліковий запис через Edge Function із `service_role`. Логін і згенерований пароль видаються курʼєру особисто.

## Чому

- Курʼєр возить чужі гроші й чужу їжу. Доступ до системи має отримувати тільки перевірена людина.
- Немає сценарію «випадковий користувач хоче стати курʼєром» — наймання відбувається офлайн.
- Простіше: не треба верифікації телефона, підтвердження email, модерації заявок.

## Як робити правильно

1. Пароль генерується **на сервері**, не в браузері адміна.
2. Показується адміну **один раз** — у момент створення.
3. **Ніде не зберігається у відкритому вигляді.** Тільки хеш у Supabase Auth. У наших таблицях паролів немає взагалі.
4. `couriers.must_change_password = true` — застосунок не пускає далі до зміни.
5. Забув пароль → адмін генерує новий. Не «подивитись старий».
6. Деактивація (`is_active = false`) миттєво розриває сесію.

## Чого робити не можна

**Зберігати згенерований пароль у таблиці**, «щоб адмін міг подивитись пізніше». Це створює базу відкритих паролів — рівно те, чого схема має уникати. Зафіксовано як B17.

**Показувати список паролів в адмінці.** Навіть «тільки для адміна». Компрометація одного облікового запису адміна = компрометація всіх курʼєрів.

## Чим платимо

- Адмін стає вузьким місцем: без нього новий курʼєр не почне працювати. Прийнятно при 2–5 курʼєрах, стане проблемою при 30.
- Немає самообслуговування при забутому паролі — потрібне втручання людини.

## Умова перегляду

При масштабуванні (> 20 курʼєрів або кілька міст) — додати самостійне відновлення пароля через SMS, зберігши ручне створення облікових записів.
