# ADR-0001: Спільна база даних із cstllife замість окремого API

**Статус:** Прийнято

## Контекст

cstllife і Rocket Delivery — два окремі фронтенди, які працюють з тими самими сутностями: замовлення, бізнеси, статуси, локація курʼєра. Клієнт бачить статус на cstllife, курʼєр змінює його в Rocket Delivery — це та сама сутність.

cstllife уже використовує Supabase (у репозиторії CSTL_NEWS є `supabase/functions`).

## Рішення

Обидва застосунки читають і пишуть у **той самий проєкт Supabase**. Синхронізація — через Supabase Realtime: обидва фронтенди підписані на ті самі таблиці.

Rocket Delivery **не будує власний бекенд** і **не спілкується з cstllife через HTTP API**.

## Чому

- Замовлення — це один рядок, а не дві копії в двох системах. Немає розсинхрону, немає «а в них статус інший».
- Realtime із коробки: заклад бачить курʼєра, клієнт бачить статус, без написання власного WebSocket-шару.
- Одна авторизація на дві системи.
- Один набір RLS-політик, а не два узгоджені між собою.
- Команда одна й маленька. Другий бекенд — це другий деплой, другий моніторинг і другий набір помилок.

## Відкинуті альтернативи

**Окремий бекенд Rocket Delivery + REST API до cstllife.** Дає чіткі межі систем, але вимагає синхронізації стану між двома базами, узгодження версій API і власної реалізації realtime. Для команди такого розміру це подвоєння роботи заради архітектурної чистоти, яка ще не потрібна.

**Дублювання даних із періодичною синхронізацією.** Гарантовано дає розходження станів. Для замовлень із грошима це неприйнятно.

## Чим платимо

- **Звʼязаність.** Зміна схеми `orders` зачіпає обидва застосунки. Потрібна дисципліна міграцій і сумісність назад.
- **Спільний ризик.** Помилка в RLS одного застосунку відкриває дані іншого. Це прямо посилює важливість [05-roles-auth-rls.md](../05-roles-auth-rls.md), особливо з огляду на витік, який уже стався.
- **Спільний ліміт.** Один тариф Supabase на два застосунки — навантаження від трекінгу курʼєрів впливає на швидкодію новинної частини. Тому локація йде через Broadcast, а не через записи в таблицю.
- **Залежність від чужого репозиторію.** Розробка Rocket Delivery заблокована доступом до CSTL_NEWS.

## Умова перегляду

Якщо навантаження від доставки почне заважати роботі новинної частини, або якщо командами стануть різні люди з різними релізними циклами — переглянути на користь окремої схеми Postgres у тому ж проєкті (проміжний крок) або окремого проєкту з реплікацією.
