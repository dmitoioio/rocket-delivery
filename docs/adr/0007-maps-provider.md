# ADR-0007: Провайдер карт і маршрутизації

**Статус:** Прийнято

## Контекст

Прототип використовує дві безкоштовні речі:

1. **Leaflet + публічні тайли OpenStreetMap** для карти в адмінці — без API-ключа.
2. **Google Maps embed** (`saddr/daddr&output=embed`) для маршруту курʼєр→клієнт і орієнтовного часу — теж без ключа.

Обидві добре працюють у прототипі й обидві непридатні для продакшену.

## Проблеми поточного рішення

**Публічні тайли OSM.** Usage policy OpenStreetMap Foundation прямо забороняє важке продакшн-використання їхніх тайлових серверів — це інфраструктура, що тримається на пожертвах. Ризик: блокування по IP у найгірший момент, без попередження.

**Google Maps embed без ключа.** Три окремі проблеми:
- **Неофіційний.** Не документований як API, може зламатись у будь-який момент без нотифікації.
- **Погано працює для велосипедного режиму в сільській місцевості.** Саме там, де ми працюємо. Маршрут для скутера ґрунтовими дорогами між селами — це не те, що Google рахує добре.
- 🔴 **Витік приватності.** Адреса клієнта передається в Google через URL — без згоди клієнта і без правової підстави. Це не «технічний борг», це обробка персональних даних третьою стороною.

## Рішення

| Задача | Продакшн-рішення |
|---|---|
| Тайли карти | Комерційний провайдер (**MapTiler** або **Stadia Maps**) з ключем, обмеженим по домену. Обидва мають безкоштовний тариф, достатній для пілоту, і легально дозволяють продакшн |
| Бібліотека карти | **Leaflet** лишається — вона провайдер-незалежна, міняється тільки URL тайлів |
| Маршрут і ETA | **Google Directions API** з платним ключем, обмеженим по домену **і по конкретному API** |
| Геокодування | **Ручний піндроп клієнтом на карті** при оформленні замовлення — основний спосіб |

## Чому піндроп, а не геокодування за текстом

В Олиці й довколишніх селах половина адрес не має нумерації. Реальна адреса — «зелені ворота, за магазином». Жоден геокодер це не розпізнає.

Тому:
- клієнт **ставить точку на карті** при оформленні — це основне джерело координат;
- текстовий `landmark` — доповнення для курʼєра, не заміна координат;
- геокодування за текстом — лише як підказка при введенні, з обовʼязковим підтвердженням точки клієнтом.

## Чим платимо

- **Гроші.** Directions API платний після безкоштовного ліміту. Заклали ~300 ₴/міс у [06](../06-financial-model.md). При зростанні обсягу це зростає — треба кешувати маршрути між тими самими парами координат.
- **Ключі в бандлі.** Ключі карт неминуче потрапляють у фронтенд. Захист — обмеження по HTTP-referrer і по конкретному API в консолі Google, плюс квоти й алерти на перевитрату. Ключ без обмежень у публічному бандлі — це чужий рахунок за твій рахунок.
- **Піндроп ускладнює чекаут.** Клієнту треба зробити зайву дію. Компенсується запамʼятовуванням адреси для повторних замовлень.

## Обовʼязкові налаштування безпеки ключа

- [ ] Обмеження по HTTP-referrer (тільки домени cstllife і Rocket Delivery)
- [ ] Обмеження по API (тільки Directions, тільки Geocoding — нічого зайвого)
- [ ] Денна квота з запасом ×2 до очікуваного обсягу
- [ ] Алерт на 50% і 80% квоти
- [ ] Окремі ключі для staging і продакшену
